# code-review — como revisar um código

## Relevância: 🔵 máxima (a lente DEV/PO se integra aqui quando necessária)

## Passos (frases curtas)
1. Leia o que o código SE PROPÕE a resolver antes dos detalhes.
2. Mantenha o foco: corretude, contrato, edge cases, simplicidade.
3. Comente com evidência (linha, comportamento, teste) — nunca achismo.
4. Sugira em vez de impor; se algo está errado, diga por quê.
5. Conclua com um resumo: pontos aceitos, pontos a corrigir.

## Pontos que exigem atenção 🔴
- Padrões do projeto: revisão respeita o padrão existente antes de sugerir novo.
- Segurança básica: dados sensíveis e inputs não podem passar batido.

## Se precisar aprofundar (lacunas opcionais)
- Custo/performance 🟡

## Critério de saída
- Revisão concluída com pontos claros e sem "funciona" sem prova.
